# Xerif website

VitePress site for Xerif: marketing home page, web flasher (`/flash`),
user docs (`/docs/*`), and a build-time changelog. Spec in
[FEATURES.md](./FEATURES.md); design tokens in [DESIGN.md](./DESIGN.md).

## Commands

All JS tooling runs through **bunx** (no npx/npm):

```sh
bun install               # once, to set up node_modules (bun.lock is committed)
bunx vitepress dev        # dev server (http://localhost:5173)
bunx --bun vitepress build  # production build -> .vitepress/dist
bunx vitepress preview    # serve the production build locally
```

## Release-driven data

Version numbers, the flash manifest, and the changelog are fetched from the
GitHub releases API at **build time** (`~/.vitepress/lib/releases.mjs`, cached
for one hour in `.vitepress/cache/`). Never hardcode versions in content.
Set `GITHUB_TOKEN` to raise the API rate limit.

## Deploy (owner)

1. Fill in `account_id` in [wrangler.jsonc](./wrangler.jsonc) (and adjust the
   route if the domain changes). The `assets.directory` points at
   `.vitepress/dist`.
2. `bunx --bun vitepress build`
3. `bunx wrangler deploy` from this directory (or `bun run deploy`).

`bunx wrangler login` once beforehand if you are not using an API token
(`CLOUDFLARE_API_TOKEN`). The custom domain `xerif.aaflalo.me` binds on first
deploy; the zone must be on the same Cloudflare account.

## Conventions

- **Attribution:** "Please support CrossPoint" appears in the hero, the
  site footer on every page, docs Acknowledgements, and the changelog.
  Never donation wording — see FEATURES.md §3 and the owner rules.
- **Search:** local search enabled; `/changelog` is excluded
  (`search: false`).
- **Dark mode:** light-first (paper) design; the dark toggle inverts to ink
  via the `.dark` token block in `.vitepress/theme/custom.css`.
- **Mobile:** every custom layout reflows to a single column at ≤ 768px.
- `public/esp-web-tools/` is generated by the build from the installed
  `esp-web-tools` package (self-hosted WebSerial installer, no CDN).
