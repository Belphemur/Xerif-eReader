# Xerif website

VitePress site for Xerif: marketing home page, web flasher (`/flash`),
user docs (`/docs/*`), and a build-time changelog. Spec in
[FEATURES.md](./FEATURES.md); design tokens in [DESIGN.md](./DESIGN.md).

## Commands

All JS tooling runs through **bunx** (no npx/npm):

```sh
bun install               # once, to set up node_modules (bun.lock is committed)
bunx vitepress dev        # dev server (http://localhost:5173)
bunx --bun vitepress build  # production build -> .vitepress/dist
bunx vitepress preview    # serve the production build locally
```

## Release-driven data

Version numbers, the flash manifest, and the changelog are fetched from the
GitHub releases API at **build time** (`~/.vitepress/lib/releases.mjs`, cached
for one hour in `.vitepress/cache/`). Never hardcode versions in content.
Set `GITHUB_TOKEN` to raise the API rate limit.

## Deploy (owner)

1. `bunx --bun vitepress build`
2. `bun run deploy` from this directory (runs the wrangler version pinned
   in `package.json`).

Wrangler resolves the account from your logged-in OAuth session
(`bunx wrangler whoami` to confirm); no `account_id` is needed in
[wrangler.jsonc](./wrangler.jsonc). The `assets.directory` points at
`.vitepress/dist`.

The custom domain `xerif.aaflalo.me` binds on first deploy; the zone must be
on the same Cloudflare account. For automated deploys, use Workers Builds —
connect the repo in the Cloudflare dashboard (see below).

## Conventions

- **Attribution:** "Please support CrossPoint" appears in the hero, the
  site footer on every page, docs Acknowledgements, and the changelog.
  Never donation wording — see FEATURES.md §3 and the owner rules.
- **Search:** local search enabled; `/changelog` is excluded
  (`search: false`).
- **Dark mode:** light-first (paper) design; the dark toggle inverts to ink
  via the `.dark` token block in `.vitepress/theme/custom.css`.
- **Mobile:** every custom layout reflows to a single column at ≤ 768px.
- `public/esp-web-tools/` is generated by the build from the installed
  `esp-web-tools` package (self-hosted WebSerial installer, no CDN).

## Workers Builds (Git integration)

To make Cloudflare deploy on every push (instead of manual `wrangler deploy`):

1. Cloudflare dashboard → **Compute (Workers) → Workers & Pages → Create →
   Workers → "Connect to Git"** (or open the existing `xerif-website` worker
   → **Settings → Build → Connect** and pick the repo).
2. Select the GitHub repo (`Belphemur/Xerif-eReader`), the `website` branch
   (later: develop/main), and set:
   - **Build command:** `bunx --bun vitepress build`
   - **Deploy command:** `bun run deploy` (wrangler is a devDependency, so
     Workers Builds uses the pinned major instead of fetching the latest at
     deploy time)
   - **Root directory:** `website`
   - **Build variables:** `GITHUB_TOKEN` (secret, to raise the releases API
     rate limit) — optional but recommended.
3. First build provisions the Worker; the custom domain `xerif.aaflalo.me`
   from `wrangler.jsonc` binds automatically (account_id is injected by
   Workers Builds).
4. Subsequent pushes to the connected branch redeploy automatically; PR
   branches get preview deployments if enabled in the worker's build settings.

Note: `assets.directory` is relative to `wrangler.jsonc`, so keep
**Root directory: website** or the build output won't be found.
